## Behavior and compatibility

Imager arrows and Ctrl+arrows call the camera model, whose image-plane
conversion previously returned float `0.0` for stationary Y. The controller
rejects that type before queueing any movement. The shared conversion now
returns integer zero and documents an integer X/Y/Z tuple contract.

X/Z matrix calculations and rounding, firmware quantization, focus controls,
travel bounds, collision checks, queue ordering and rejection behavior remain
unchanged. The model also supplies nozzle dataset capture and pixel-position
helpers; both imaging windows have automated shortcut coverage. No firmware
handler, protocol, timing or controller safety behavior is changed.

Firmware SHA-256 remains
`ff40b46ff1a3273d6996bfafda04fea0f5971feac3563eef0468a900fc08fb45`, identical
to v1.3.2. Runtime dependency declarations, canonical machine-data schema,
execution-calibration version 4, and execution-data compatibility declarations
are unchanged. `requires_firmware` is null; this patch alone needs no firmware
flash. Installation evidence remains subject to the normal durable firmware
state, artifact and SAFE checks.

## Discovery, publication and recovery

The proposed stable index moves from v1.3.2 to v1.3.3. Preserve the exact rc.11
pointer, RC series, and the three reviewed direct legacy source versions:
v1.2.0-rc.6, v1.2.0, and v1.3.0-rc.1. Stable manifests retain schema v1.
Direct legacy deployment still requires guarded migration, exact firmware and
recovery evidence, and an attended canary; this patch does not expand cohorts.

Rollback remains null because matching capability declarations alone do not
qualify an exact upgrade/calibrate/rollback/reload campaign. Preserve calibration
measurements, committed counts, progress and immutable revisions, and use
protected current-version or exactly qualified compatible-bundle recovery.
Existing large-optimizer and arbitrary long-session timing limitations remain.

After publication approval, tag the accepted metadata revision, run
`tools/validate_release_metadata.py --check-tags`, and publish the tag before
merging the release-preparation PR into main or advancing stable's index.
Main integration must preserve the exact tagged tree. Verify stable ancestry
before fast-forward publication, then verify public refs and stable discovery.
The normal production app can then select v1.3.3 through its guarded stable
updater; do not manually switch the protected Pi production checkout.

Before publication, preparation can be abandoned or reverted without changing
installed production code, machine data or firmware. Do not advertise or
configure an unqualified historical rollback target.
