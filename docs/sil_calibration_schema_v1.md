# SIL Synthetic Calibration Schema Version 1

Milestone 3 defines two simulation-only JSON contracts. They describe
deterministic calibration candidates; they are not physical calibration
records and are never written into an experiment directory by the provider.

## Identities

| Contract | `schema_id` | Version |
| --- | --- | ---: |
| Request | `labcraft.sil_calibration_request` | 1 |
| Result | `labcraft.sil_calibration_result` | 1 |

Provider version 1 is identified as `milestone-3-v1`. Named profiles use
integer profile version `1`.

## Request Fields

| Field | Type | Requirement |
| --- | --- | --- |
| `schema_id`, `schema_version` | string, integer | Exact request identity and version 1 |
| `provider_version` | string | Exactly `milestone-3-v1` |
| `profile_id`, `profile_version` | string, integer | Registered profile and version 1 |
| `seed` | integer | Inclusive range `0..2^63-1`; booleans rejected |
| `virtual_run_id` | string | Nonempty virtual run identity |
| `printer_head_id`, `stock_id` | string | Nonempty virtual identities |
| `factor_name`, `option_name`, `is_fill` | string, string/null, boolean | Calibration target identity |
| `requested_mode` | string | `droplet` or `stream` |
| `nominal_volume_nL` | number | Finite and within 1–250 nL |
| `volume_variation_fraction` | number | Finite in `[0, 1)`; derived interval remains within 1–250 nL |
| `pressure_bounds_psi` | two-number array | Ordered inclusive bounds within 0.3–5.0 psi |
| `pulse_width_bounds_us` | two-integer array | Ordered positive inclusive bounds |

Missing and unknown fields are rejected. Constructors normalize finite numeric
values and serialize tuple bounds as JSON arrays.

## Result Fields

The result repeats every request field so retained evidence remains
self-contained. It then adds:

| Field | Type | Requirement |
| --- | --- | --- |
| `request_fingerprint` | string | SHA-256 of the complete normalized request |
| `result_fingerprint` | string | SHA-256 of the normalized result excluding this field |
| `measured_volume_nL`, `effective_volume_nL` | number/null | Finite when present; null only for negative evidence |
| `original_printing_mode`, `applied_printing_mode` | string | `droplet` or `stream` |
| `pw_us`, `pressure_psi` | integer, number | Within the retained request bounds |
| `run_id`, `phase`, `timestamp` | strings | Virtual run; `sweep`/`stream`; derived UTC timestamp |
| `source_row_fingerprint` | six-value array | Run, phase, timestamp, pulse width, pressure, measured volume |
| `application_valid` | boolean | True exactly when `validation_errors` is empty |
| `validation_errors` | string array | Deterministic application-contract failures |
| `synthetic_limitations` | string array | Exact provider-v1 evidence limitations |

The source-row numeric values use the application's existing nine-decimal
normalization. The timestamp is generated by adding a fingerprint-derived
number of seconds to a fixed year-2000 UTC epoch. It is a stable virtual
identity, not the time generation occurred.

## Canonicalization And Randomness

Canonical JSON uses:

```python
json.dumps(
    payload,
    ensure_ascii=False,
    allow_nan=False,
    sort_keys=True,
    separators=(",", ":"),
).encode("utf-8")
```

Each `generate()` call constructs its own `random.Random` from the complete
request fingerprint. Generation therefore does not depend on provider call
order and does not inspect or change process-global random state.

## Profile Semantics

| Profile | Result behavior |
| --- | --- |
| `nominal_droplet` | Samples within a fully droplet-scale request interval |
| `nominal_stream` | Samples within a fully stream-scale request interval |
| `droplet_to_stream` | Retains original droplet mode and applies stream mode |
| `stream_to_droplet` | Retains original stream mode and applies the exact low request boundary below 40 nL |
| `low_volume_boundary` | Uses the exact inclusive lower volume bound |
| `high_volume_boundary` | Uses the exact inclusive upper volume bound |
| `invalid_outlier` | Produces a finite value above the request interval |
| `missing_measurement` | Produces null measured and effective volumes |

The last two profiles return valid result-schema evidence with
`application_valid=false`. `validate_for_application()`,
`to_application_summary_row()`, and `to_application_calibration_step()` raise
`CalibrationApplicationError` for them.

Valid summary rows use the established `run_id`, `phase`, `timestamp`,
`pw_us`, `pressure_psi`, `mean_nL`, `valid`, and `printing_mode` fields. Valid
calibration steps use the existing droplet pressure-entry or stream terminal
result shapes. Synthetic stream results include no measurements or image
references and carry `synthetic_result_without_camera_evidence`.

## Evidence Limitations

Every result states that it provides no evidence for:

- cameras, optics, segmentation, or image analysis;
- physical ejection or volume accuracy;
- physical pressure response or refuel behavior;
- motion/collision safety, firmware, or protocol behavior.

The provider performs no filesystem, Qt, Model, Controller, serial, balance,
camera, hardware-factory, or authoritative-state operation. Milestones 4A–4C
own presentation and application through simulation-gated versions of the real
application result and workflow surfaces.

Directional droplet-to-stream generation from source volumes that cannot form
a valid symmetric v1 interval is represented by the additive
`sil_calibration_schema_v2.md` contract. V1 serialization and fingerprints are
unchanged.
